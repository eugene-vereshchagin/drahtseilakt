# Формат файлов Virtools (.nmo / .cmo)

Как `crates/nmo` читает уровни Ballance и любительские карты. Восстановлено по самим файлам — файлам игры и
примерно 600 любительским картам, которые все читаются целиком, — с константами идентификаторов из
заголовков Virtools SDK. Все числа little-endian; «слово» — 32 бита.

## Контейнер

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 8 | сигнатура `Nemo Fi\0` |
| 8 | 4 | контрольная сумма |
| 12 | 4 | версия Virtools (`0x13022002` у Virtools 2.1 из Ballance, `0x26052005` у 3.5) |
| 16 | 4 | версия файла (8 во всех встреченных; header 1 есть начиная с 5) |
| 20 | 4 | ноль |
| 24 | 4 | режим записи (бит `8`: файл сжат целиком) |
| 28 | 4 | header 1, размер в файле |
| 32 | 4 | данные, размер в файле |
| 36 | 4 | данные, размер после распаковки |
| 40 | 4 | число менеджеров |
| 44 | 4 | число объектов |
| 48 | 4 | наибольший id объекта |
| 52 | 4 | версия продукта |
| 56 | 4 | сборка продукта |
| 60 | 4 | header 1, размер после распаковки |

Дальше header 1, затем данные. Часть сжата zlib ровно тогда, когда её размер в файле и размер после
распаковки различаются. После данных файлы Virtools 3.5 дописывают **встроенные файлы** до конца: имя
(слово длины + байты) и содержимое (слово размера + байты); обычно только `vtthumbnail.jpg`, у некоторых карт
ещё звуки и картинки.

**Контрольная сумма**: Adler-32 с начальным значением 0 вместо 1 по 64-байтному заголовку с обнулённым
полем суммы, затем по header 1 и данным в том виде, как они лежат в файле (без встроенных файлов). Она
совпадает во всех встреченных файлах; читатель сообщает о несовпадении, а не отказывает, потому что
неизвестно, проверяет ли её оригинальная игра.

## Header 1: таблица объектов

На каждый объект: id, id класса, индекс в данных, длина имени, байты имени (в кодировке того, кто писал, —
в китайских картах часто GBK). Дальше зависимости от плагинов, они не нужны.

## Данные: менеджеры и объекты

Сначала по записи на менеджер (GUID: 2 слова, слово размера, chunk), затем по записи на объект в порядке
таблицы (слово размера, chunk; размер 0 — chunk нет).

**State chunk**: слово версии (версия данных, id класса, версия chunk и биты опций — по байту), число слов,
сами слова, затем необязательные списки по битам опций (`1` id объектов, `4` подчинённые chunk, `2`
менеджеры; каждый — число слов и слова). Опция `8` означает, что ссылки на объекты — индексы в таблице
объектов; `0xFFFFFFFF` — пустая ссылка.

Внутри слов поля сгруппированы под **идентификаторами**, которые образуют связный список:
`[идентификатор, индекс следующего идентификатора (0 в конце), поля...]`. Строка — длина в байтах и байты,
дополненные до целых слов; после завершающего NUL бывает мусор.

## Классы, из которых состоит уровень

| Класс | Id | Идентификатор | Поля |
|---|---|---|---|
| любой объект | | `0x4` / `0x18` | есть: скрыт / скрыт по иерархии |
| Группа | 23 | `0xFFFFF` | число, ссылки на членов |
| Материал | 30 | `0x1000` | diffuse, ambient, specular, emissive (слова ARGB), степень блика (float), ссылка на текстуру, цвет рамки, слово режимов, слово флагов |
| Текстура | 31 | `0x10000` | число слотов, имя файла каждого слота |
| | | `0x20000` | встроенные пиксели: число слотов, затем бит на пиксель, ширина, высота, маски A R G B, слово, число пикселей, пиксели; `[1, 0]`, если пиксели лежат в файле |
| Меш | 32 | `0x100000` | слоты материалов: число, затем (ссылка, слово) на слот |
| | | `0x20000` | число вершин, флаги сохранения, размер (слов данных + 1), затем позиции, цвета, спекуляры, нормали, UV — как скажут флаги |
| | | `0x10000` | число граней, затем по два слова на грань: индексы 0 и 1 (по 16 бит), индекс 2 и слот материала |
| 3D-сущность / объект, камера, свет | 33, 41, 34, 35, 38, 39 | `0x100000` | слово, флаги, оси 3×3 (строками), позиция — мировая матрица |
| 3D-объект | 41 | `0x4000` | ссылка на текущий меш, число, ссылки на меши |
| Массив данных | 52 | `0x1000` | столбцы: число, затем имя (строка) и тип (1 int, 2 float, 3 строка, 4 объект, 5 параметр + GUID типа) |
| | | `0x2000` | строки: число, затем по значению на столбец |

**Флаги сохранения вершин**: `0x1` один цвет на всех, `0x2` один спекуляр на всех, `0x4` нормалей нет
(читатель считает гладкие сам), `0x8` один UV на всех, `0x10` позиций нет.

**Слово режимов материала**, полубайты от младшего: режим смешивания текстуры, фильтр min, фильтр mag,
коэффициент источника, коэффициент приёмника (коэффициенты Virtools: 1 zero, 2 one, 3 src colour, 4 inv src
colour, 5 src alpha, 6 inv src alpha, …), затенение, заливка. **Слово флагов**: бит `0x1` двусторонний,
`0x2` запись глубины, `0x8` альфа-смешивание, `0x10` альфа-тест; байт 1 — сравнение глубины, байт 2 —
сравнение альфы, байт 3 — порог альфы.

## Что игра берёт из уровней

Уровень содержит геометрию и **группы**; логика игры живёт в `base.cmo` и работает по именам групп:
`PS_Levelstart` (старт; его ось Z смотрит назад, на камеру), `PR_Resetpoints` (центры шара по секторам),
`PC_Checkpoints`, `PE_Levelende`, `Sector_NN`, `Phys_Floors` / `Phys_FloorRails` / `Phys_FloorStopper`
(столкновения), `P_*` (модули и предметы, их модели — в `3D Entities/PH/*.nmo`), группы звуков. Объекты
этих групп, у меша которых нет материала, — заглушки редактора, их никогда не рисуют. Небо и стартовый шар
каждого уровня — в массиве данных `AllLevel` из `3D Entities/Levelinit.nmo`.
