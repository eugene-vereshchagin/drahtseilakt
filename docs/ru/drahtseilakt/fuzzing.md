# Фаззинг парсеров

У каждого читателя файла, который игра написала не сама, — уровней и любительских карт `.nmo`/`.cmo`, открытого
формата уровней, картинок, звуков, образа CD и его архива InstallShield, реплеев, файлов подсказок, `level.txt` папок
уровней, звуковых тем, файлов настроек и рекордов — есть фазз-цель. Запустить их можно двумя способами.

## Стабильный фаззер (работает везде, без сети)

`crates/fuzzkit` — маленький мутационный фаззер без зависимостей. Каждая цель — тест с `#[ignore]` рядом с остальными
тестами парсера; он мутирует корпус затравок (переворот битов, «интересные» значения, вставки, удаления, копии,
склейки, обрезки, сдвиги полей длины, а для текстовых форматов — строки, слова и числа) фиксированным генератором
xorshift, так что любой вход можно получить снова по его номеру. Каждый вход идёт под охраной: паника ловится, вход,
работающий дольше срока или берущий больше памяти, чем позволено цели, завершает прогон, а аварийное завершение
(отказ в памяти под лимитом адресного пространства, переполнение стека) находится повтором последнего отрезка.

```sh
scripts/fuzz.sh                    # все цели, по 600 с, по 4 сразу
scripts/fuzz.sh 3600 2 nmo_file    # одна цель, час
FUZZ_SECS=60 cargo test --release --offline -p level --test fuzz fuzz_nmo_file -- --ignored --nocapture
```

Цели: `nmo_file`, `nmo_chunk`, `nmo_patch`, `open_level`, `script_json` (крейт `level`); `image`, `gputex`, `gputex_data`, `level_txt`, `theme_txt`, `pack_txt`, `sound_table`
(`gamedata`); `disc_image`, `cue_sheet`, `iscab` (`cdimage`); `replay`, `hints`, `zones`, `learned`, `wav`, `ogg`, `highscore`,
`settings`, `level_sim` — уровень, загруженный и сыгранный секунду: так чужая карта проходит дальше читателя, в
физику и правила — и `module_sim` — файл модуля вместо того, что использует оригинальный уровень (папка уровня может
принести свой), при наличии копии игрока (игра, `crates/game/src/fuzz_tests.rs`).

Затравки — маленькие синтетические файлы, которые делают сами тесты, собственные файлы игры и, если они есть, файлы
игрока (`OPENBALLANCE_DATA`, `OPENBALLANCE_MAPS`, оригинальные и любительские уровни профиля): они читаются во время
прогона и никогда не попадают в репозиторий. `FUZZ_NO_REAL=1` их отключает.

Настройки: `FUZZ_SECS` (время на цель), `FUZZ_SEED` (какие входы; `scripts/fuzz.sh` берёт новый каждый раз),
`FUZZ_TIMEOUT_MS` (срок одного входа, 10 с), `FUZZ_RSS_MB` (предел памяти), `FUZZ_REPRO=<файл>` (прогнать один вход и
сказать, что с ним).

Находки ложатся в `fuzz/artifacts/<цель>/` (git их не видит): `crash-*`, `hang-*`, `oom-*` или `abort-*`, каждая —
`.bin`, `.txt` с описанием и минимизированный `.min.bin`. Исправление получает регрессионный тест рядом с парсером и
синтетический воспроизводящий вход (никогда не данные игры) в `fuzz/regressions/<цель>/`, который прогоняют обычные
тесты.

## cargo-fuzz (libFuzzer, nightly)

`fuzz/` — крейт cargo-fuzz вне рабочего пространства (сборке игры он не нужен). Его цели вызывают те же функции, что и
тесты стабильного фаззера:

```sh
FUZZ_DUMP_CORPUS=1 cargo test --release --offline -p level --test fuzz fuzz_nmo_file -- --ignored  # затравки -> fuzz/corpus/
cd fuzz && cargo +nightly fuzz run nmo_file corpus/nmo_file
```

Игра — бинарный крейт, поэтому из её собственных парсеров цель cargo-fuzz есть только у `replay` (он самостоятелен);
остальные (`hints`, `zones`, `learned`, `wav`, `ogg`, `highscore`, `settings`, `level_sim`, `module_sim`) идут на стабильном фаззере.
