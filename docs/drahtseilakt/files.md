# Where the game keeps its files

The game reads two kinds of files: the **shipped assets** (`assets/`: fonts, own parts, levels, factory mods, sound themes) and the **player's data** (settings, replays, highscores, imported and made levels, the player's packs, mods and sound themes). Both layouts below work with the same program.

**Shipped assets**, first found wins: `$DRAHTSEILAKT_ASSETS`; `assets/` beside the program; `../Resources/assets` (a macOS .app bundle); `../share/drahtseilakt/assets` (installed under a prefix: the Linux packages put the program in `/usr/bin` and the data in `/usr/share/drahtseilakt/assets`); and only for developers, the source tree the program was built in (`assets/` three folders above `target/release`, or the path it was compiled in); last, `drahtseilakt/assets` in each folder of `$XDG_DATA_DIRS` (default `/usr/local/share:/usr/share`). Release packages: [release.md](release.md). At the start the game prints one line, `paths: assets ... | data ... (portable|per-user)`, and a session log repeats it.

**Portable** (copy the folder and play; nothing outside it is touched): `drahtseilakt(.exe)`, `assets/` and an empty file `portable.txt` side by side. The player's data is then in `data/` beside the program. The rule is just that file: no `portable.txt`, no portable mode.

**The portable build** (`scripts/make-portable.sh`) makes such a folder with the game and the toolbox, one per system: `drahtseilakt-portable/<os>-<arch>/` beside the checkout by default (`linux-x86_64`, `windows-x86_64`; `--target linux|windows`, another output folder as its argument). It builds both programs in release, offline, and puts together: the game (`drahtseilakt.exe`; on Linux the launcher `drahtseilakt` and the program `drahtseilakt.bin`, with `lib/` holding the sound, input and udev libraries `libasound`, `libudev`, `libcap`, their licences in `lib/LICENSES/`), the toolbox (`drahtseilakt-toolbox(.exe)`; it finds `portable.txt` the same way, so what it converts and remasters goes into this `data/`), `realesrgan/` (Real-ESRGAN from the toolbox's pinned download for that system, checked against its SHA-256, with `LICENSES.txt`; on Windows with the `vcomp140.dll` the release ships; a build without it is refused), on Windows the MinGW DLLs the programs import, `assets/` (everything shipped, checked against its `SHA256SUMS`; not `mods-dev/`, `own/make/` or Python caches), `README.txt`, `LICENSE`, `CREDITS.md`, `THIRD-PARTY.md`, `VERSION` (both repositories' `git describe`), `portable.txt` and an empty `data/`. That is a release build, for every system: no development mods. `--dev` (Linux only) makes a development build into `<os>-<arch>-dev/`: with `assets/mods-dev/` (god-mode), marked DEV in `VERSION` and `README.txt`. Run again on the same folder it replaces the programs and assets and keeps `data/`. `--with-originals DIR` imports the original levels from a copy of Ballance into `data/` as the game's import does: only for private test builds, never for a published one.

**Installed** (the program and `assets/` in one folder, e.g. `/opt/drahtseilakt`, `C:\Program Files\Drahtseilakt`, an .app's Resources): the player's data is in the per-user folder, `$XDG_DATA_HOME/drahtseilakt` (default `~/.local/share/drahtseilakt`) on Linux, `%APPDATA%\drahtseilakt` on Windows, `~/Library/Application Support/drahtseilakt` on macOS. The player's packs, mods and themes there are found in addition to the shipped ones.
