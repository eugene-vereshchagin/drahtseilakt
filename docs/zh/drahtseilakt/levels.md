# 关卡存放在哪里

游戏如何保存其关卡，已于 2026-11-02 与项目所有者商定（decisions.md，“关卡存放在一个文件夹中，分四类”）。显示关卡的菜单见 [menu.md](menu.md)。

## 文件夹

所有关卡都位于游戏数据文件夹（Linux 上为 `~/.local/share/drahtseilakt/`，Windows 上为 `%APPDATA%\drahtseilakt\`，macOS 上为 `~/Library/Application Support/drahtseilakt/`）中的同一个文件夹 `levels/` 里，按来源和格式划分：

| 文件夹 | 内容 | 来源 | 模式 |
|---|---|---|---|
| `levels/original/` | 原版游戏：`base.cmo`、`3D Entities/`、`Textures/`、`Sounds/` 等，并已安装第 13 关的扩展包 | 由游戏从玩家已安装的游戏或 CD 中复制 | 经典模式和扩展模式 |
| `levels/community/` | 自制地图：每个关卡一个文件夹，里面是一个 `.nmo` 或一个开放格式关卡（见下文） | 由玩家下载，`drahtseilakt-toolbox import-maps` 把下载内容整理成文件夹；文件夹中的 README 说明去哪里获取 | 扩展模式 |
| `levels/remastered/` | 转换为开放格式的原版关卡，纹理放大到 4K–8K，并加上现代画面所需的其他内容 | 由 `drahtseilakt-toolbox remaster` 在玩家机器上根据 `original/` 生成；从不分发 | 扩展模式 |
| `levels/open/` | 开放格式的关卡：直接用它制作的，或转换后的自制地图 | 由玩家制作；部分随游戏附带 | 扩展模式 |

经典模式只看到 `original/`；扩展模式看到全部四个（menu.md）。

## 一个关卡就是一个文件夹

*所有者 2026-11-03 的决定*（decisions.md，“一个关卡就是一个文件夹”）。`community/` 和 `open/`（以及 `remastered/`）里放的是关卡，而不是压缩包解压出来的任何东西：自定义关卡菜单显示一个按难度和标题排序的扁平关卡列表，没有需要打开的文件夹。关卡作者和玩家需要知道的一切都集中在 [making-levels.md](making-levels.md)。

- **一个关卡是类别文件夹中直接的一个文件夹**，其中恰好有一个关卡：一个 `.nmo` 文件，或一个开放格式的关卡（`level.gltf`、`level.bin`、`textures/`；open-format.md）。开放格式清晰明了，便于手工完成或修改：普通的 glTF 和 PNG 文件。
- 旁边都是可选的：`level.txt`，简单的 `键 = 值` 行（`title`、`author`、`version`；`title.<代码>`，关卡在另一种语言中的标题，例如 `title.ru`，菜单使用该语言时显示；`order`，一个数字，使关卡按此顺序排在没有该键的关卡之前；`difficulty`，关卡的难度，一个 1（简单）到 10 的整数，其他任何值都视为未知；`hidden = yes`，不出现在随游戏附带的关卡列表中，测试关卡就是这样；`#` 开头为注释，其他键被忽略），README（`README.txt` 或 `README.md`），预览图（`preview.png` 或 `preview.jpg`），以及关卡使用的资源文件夹（`textures/`、`game/`）。
- **标题**取 level.txt 的 `title`（英文；其他语言写作 `title.<代码>`），否则取文件夹名。标题会被清理（去掉控制字符、文字方向覆盖符和其他不可见格式字符，连续空格合为一个），并按单词截断到 **40 个字符**（按字符而非字节计），末尾加“…”，游戏字体把它画成 "..."。游戏显示关卡名的所有地方（菜单、加载画面、窗口标题）都显示这个标题。只有当 level.txt 是不超过 4 KiB 的普通文件时才会读取；更大的文件或链接被忽略。
- **直接放在类别文件夹中的单个 `.nmo` 也是一个关卡**，以文件名命名：试玩地图的最简单方式。
- 菜单忽略：关卡文件夹中的其他文件、其中的所有文件夹（不嵌套）、隐藏名称（以点开头）、链接（从不跟随），以及没有关卡或有多个关卡的文件夹（多个 `.nmo`，或 `.nmo` 与 `level.gltf` 并存）：它们不是关卡，会在控制台中列出。
- 没有“合集”这一概念：13 个旋转版原版关卡就是 13 个关卡文件夹（“45-Degree Rotated - Level 07”）。
- `drahtseilakt-toolbox import-maps <文件夹>` 把下载的合集整理成这种结构：每张地图一个文件夹，包含它的 `.nmo`、作为预览的图片，以及说明来源的 level.txt（文件夹名不得不丢掉字符时还写入完整标题）。通用文件名（`Level_07.NMO`）按其合集命名；同一文件出现两次只算一个关卡；压缩包只列出、不打开；名称在 Linux、Windows 和 macOS 上都可用（无保留名称，末尾无点或空格，最多 40 个字符，第二个 “Hello Mars” 编号为 “(2)”）；源文件只读。再次运行只添加新内容。使用 `--catalogue CustomMapList.md`（社区的地图列表）时，它根据目录填写 level.txt：英文标题、作为 `title.zh` 的原名、作者和难度（目录中的 1–5 乘以二）；既不在目录中也没有 readme 的地图不会被导入，而是与压缩包和不是单个关卡的文件夹一起放到 `levels/community-unsorted/` 中，并附一个说明原因的 README.txt（`--unsorted 文件夹` 可选择另一个文件夹）；`--refresh` 对以前导入的文件夹做同样的处理，只重写其中的 level.txt 文件。菜单按难度、其次按标题列出；难度未知的关卡排在其后，没有 `title`（以文件夹命名）的关卡排在最后。

## 随游戏附带的关卡

我们自己的关卡随游戏放在其 `assets/levels/` 中，每个关卡一个开放格式的文件夹，只用我们自己的部件制作（assets/own，[resources.md](resources.md)），因此完全不需要原版的副本也能游玩。菜单把它们与 `levels/open/` 中的开放格式关卡一起显示：没有副本时在 Start 下（列表“Our levels”），在扩展模式的“Open format”下则始终显示。它们由 `assets/own/make/` 中的脚本生成（`levelkit.py` 用轨道块和部件的替身搭建关卡；`make_test_level.py` 生成第一个关卡 `Parts_Test`：几百个单位长的轨道，每个部件都在轨道上或旁边，另有每种防护各一段轨道，供测试使用；它的 level.txt 中的 `hidden = yes` 使它不出现在玩家的列表中，仍可用 `--open` 打开），生成结果已提交到仓库。它们的许可证与游戏相同（GPL-3.0-only）。

**关卡以文本编写。** 每个文件夹中有它的描述 `level.lvl`，用一种小语言写成，由 `assets/own/make/leveldsl.py` 读取；它借助 `levelkit.py` 在旁边写出关卡（`level.gltf`、`level.bin`、`textures/`、`level.txt`）。关卡 `textures/` 中只有它自己的纹理文件（它那一套地板、路缘、阴影和斜坡）；所有关卡共用的纹理以游戏纹理名称引用（`game:` 图片，open-format.md），由所选纹理包绘制（[packs.md](packs.md)）。描述像海龟绘图一样铺设轨道：一个光标（地面顶面上的一个点和一个朝向，开始时沿 +X，左边是 +Z）随每一段前移，部件放在光标所在之处。一行是一条命令；`#` 开始注释：

```
title Paper Winds            # 关卡名称；title.ru、title.de、title.zh：其他语言中的名称
order 3                      # 它在列表中的位置
difficulty 3                 # 难度，1 到 10（level.txt 的 difficulty：菜单按它排序）
sky C                        # A、B、C 或按名字的天空：Mountains、Sea……（见下）
music 3                      # 主题，1 到 5
bonus 300                    # 关卡奖励
ball wood                    # 起始球
columns 45                   # 每隔 45 单位路程在地面下放柱子，仅为外观

start                        # 起点平台；路从它的前缘继续
safety railings              # 轨道如何留住球：railings、gutter、border 或 none（见下）
width 12                     # 地面宽度（borders off|on，surface stone|wood）
floor 30                     # 一段长 30 的直地面（floor 30 up 4、floor 30 down 6：坡道）
right 90 26                  # 以半径 26 向右转 90 度的地面（left A R）
point                        # 此处一个额外分数（life：额外生命；side S、ahead A：在旁边、更前方）
trafo paper                  # 一个变球器
fan ahead -5                 # 此处后方 5 的风扇：纸球在上面升到其地面上方约 17
gap 4 up 12                  # 前方 4、上方 12：不建任何东西（一次跳跃，或风扇把球送到的地面）
checkpoint                   # 检查点（朝向为 90 的倍数）：下一小节开始
finish                       # 气球，在前方 22 处
```

此外：`rails L`、`rails-left A R`、`rails-right A R`（轨道，也可向上或向下）；`box`、`dome`、`loose wood|stone|paper`；`seesaw`（架在与其板长相同的缺口上）、`platebridge`（14.8 的缺口）、`swingbridge`（5 的缺口中的秋千）、`sack`、`arms`、`flaps`；`module P_Modul_NN` 配合 `ahead`、`side`、`up`、`turn`、`tilt` 放置其他任何部件；`move`、`turn`、`mark NAME` 和 `back NAME` 只移动光标而不建造。完整列表在 leveldsl.py 的开头。

`railing left|right|both|off` 从此处起沿地面边缘设置钢护栏，适用于任何截面（第 1 关：槽形地面，可能掉落处加护栏）。原版的两个谜题有各自的命令：`crateblock`（箱子上的石块，P_Modul_34：横跨道路的 6 宽的槽，石块立在槽中、压在自己的箱子上，箱子位于描述在槽下铺设的低 5 的地面上；该地面上的球把箱子从石块下推出，石块便下滑到与道路齐平）和 `pusher left|right`（P_Modul_01：横跨最宽 6 的道路的 1.6 宽的槽，推杆的石块堵住道路，其靶板在该侧伸出边缘 5，位于低 2.5 的地面上方，球从那里把石块推离道路）。其下的地面用 `mark`、`move`、`turn` 和 `back` 铺设。

**拐角、广场与布景**（2026-11，第 1 关重建；`assets/own/make/levelparts.py`）。`corner left|right [rail] [gap G]` 是生硬的直角拐角：上一段地面的末端是斜接环（截面立在角平分线上，宽 1/cos 45 倍），与后一段共用，外角被填满，截面（槽、木板）不断开；`rail` 在外侧两边各 8 设护栏，`gap` 在直行方向留 G 的缺口。`plaza W L [brick|kerb] [stone|wood] [gap SIDE C W]... [fence SIDE...]` 是从后缘中点起的平整方场，除缺口外有砖边或低缘，`fence` 指定的边设护栏；`disc R [rim] [ring [gap W]]` 为圆形平台；`pit L [depth D] [wall LEN] [side S]` 为路上的坑和挡墙；`mark`/`back` 开始和结束侧支。独立布景（仅绘制）：`lamptower`、`mast`、`plinth`、`garland`、`wallblock`、`wlamp`、`lighthouse`；`scatter D` 沿路径每约 D 单位在远离地面处布置灯塔、桅杆和基座。`loose KIND lead` 与 `plug` 不做通行检查。广场、圆盘和坑比接续的地面低 0.03（同高的两块平面会被接缝测试视为裂缝）。

**轨道如何留住球**（`safety`）：原版的帮助随关卡递减，我们的关卡也照此安排。在原版十三个关卡上测得（其地面的边缘，只取数字）：第 1、3、5 关约三分之二的地面边缘是凹形截面（地面向边缘在 2.5 的宽度上升高 0.7：一条把偏离的球滚回中间的槽；三分之一是光边），从第 6 关起只有四分之一到三分之一（其余为光边）；凸起的墙很少（只有第 4 关的木制半管和第 12、13 关的几段）；钢护栏（一根在地面上方约 2.6 的管子，装在立柱上）沿地面边缘延伸：第 1、2 关约 490 和 420 个单位，第 3 至 8 关 130 到 540，第 9 至 11 关不到 90，第 12 关没有。我们的关卡走同样的路，只是更分明：第 1 关是槽形地面，并在可能掉落处设护栏（起点周围、弯道外侧、平台上、有落差的地面旁），与原版第一关一样，第 2 关有护栏，第 3、4 关是砖砌挡边（第 3 关有一段护栏），第 5 至 8 关是槽形地面（第 5 关有一段挡边，第 8 关最后一段是光地面），第 9、10 关是光地面（第 9 关第一段是槽形）。`safety 类型` 从此处起设定它（文件中的第一个是关卡的类型）；`borders off` 使此后的地面为光地面，`borders on` 恢复关卡的类型。各类型：

**天空。** `sky` 选择关卡周围的天空盒：`A`、`B`、`C`（我们自己的，在云海之上，与原版的字母对应），或按名字选择一种摄影天空：`Mountains`（雾霭群山上的晚霞，峰顶有雪）、`Forest`（森林树冠上的夏日云朵，有林间空地和湖泊）、`Sea`（日落时平静的大海，倒映着云）、`Storm`（暗海上的厚重乌云和白浪）、`Sunset`（云海上的金色日落）、`Clouds`（云海上的夏日）、`Night`（群山环绕的暗湖上的银河）、`Desert`（傍晚的红色峡谷）、`Mist`（山谷里有雾的丘陵上的暮光）。它们的天空是 Poly Haven 的 CC0 照片；地平线以下的一切由 `assets/own/make/make_skies.py` 绘制，像从高空俯瞰，因此赛道高悬其上（`assets/own/CREDITS.md`）。其他任何名字都是关卡文件夹或纹理中的一组文件 `Textures/Sky/Sky_<名字>_<面>`（Front、Right、Back、Left、Down，如有还有 Top）；名字由字母、数字、`_` 和 `-` 组成。命令行的 `--sky 名字` 可让任何关卡换一种天空来玩。

**云海。** 在 `Sunset` 和 `Clouds` 天空下，我们的关卡悬在一片积云海之上，游戏把它作为体积绘制（`crates/game/src/clouds.wgsl`）：由可平铺噪声构成的云团，被天空的太阳照亮（迎光处明亮，阴影里呈蓝紫色），也被上方的天空照亮，远处融入天空自己在地平线上的雾霭；柱子和支架没入其中。在 `Mountains`、`Forest`、`Mist` 和 `Desert` 下，它是破碎的云带，透过空隙能看到远在下方的大地。关卡工具包根据天空的光照（`assets/own/make/sky_light.json`，由 `make_skies.py` 写出）和它自己的表（`levelkit.py`，`CLOUD_SEA`）把它写进关卡设置（`clouds`，见 [open-format.md](open-format.md)）；关卡可用 `clouds cover C below B thickness T size S` 修改（任选其中几项：云量 0..1；云顶在最低地面下方 B，默认 35；厚度 T，默认 110；单朵云大小 S，默认 85），或用 `clouds off` 去掉它。原版关卡没有云海。设置文件中的 `cloud-quality`（`low`、`medium`（默认）、`high`；`off` 不绘制）决定绘制的精细程度，关闭 *Clouds?* 也会隐藏它（见 [menu.md](menu.md)）。在 RTX 3060、2560×1440 下，它每帧约耗时 3.5、4.5 和 6 毫秒（low、medium、high）。`make_skies.py` 生成的 `Sunset` 和 `Clouds` 在地平线以下只有雾霭：它们的云海由游戏绘制，关卡工具包会把它写进使用这些天空的关卡；没有云海的关卡（`clouds off` 或用其他方式制作的）在下方只显示雾霭。

**轨道如何留住球**（`safety`）：原版的帮助随关卡递减，我们的关卡也照此安排。在原版十三个关卡上测得（其地面的边缘，只取数字）：第 1、3、5 关约三分之二的地面边缘是凹形截面（地面向边缘在 2.5 的宽度上升高 0.7：一条把偏离的球滚回中间的槽；三分之一是光边），从第 6 关起只有四分之一到三分之一（其余为光边）；凸起的墙很少（只有第 4 关的木制半管和第 12、13 关的几段）；钢护栏（一根在地面上方约 2.6 的管子，装在立柱上）沿地面边缘延伸：第 1、2 关约 490 和 420 个单位，第 3 至 8 关 130 到 540，第 9 至 11 关不到 90，第 12 关没有。我们的关卡走同样的路，只是更分明：第 1、2 关有护栏，第 3、4 关是砖砌挡边（第 3 关有一段护栏），第 5 至 8 关是槽形地面（第 5 关有一段挡边，第 8 关最后一段是光地面），第 9、10 关是光地面（第 9 关第一段是槽形）。`safety 类型` 从此处起设定它（文件中的第一个是关卡的类型）；`borders off` 使此后的地面为光地面，`borders on` 恢复关卡的类型。各类型：

- `railings`：两侧边缘的钢护栏，横杆在地面上方 1.3 和 2.6，立柱每 6 个单位一根，与原版一样属于轨道的物理组；
- `gutter`：原版的凹形截面地面，边缘比平坦的中间高 0.7，在 2.5 的宽度内分两个面升高；
- `border`：两侧宽 1、高 2.2 的砖砌挡边，用菜单场景的砖。高过球心（球的半径为 2），球正面撞上挡边而被弹回：更低的挡边（1.4）会被以每秒 25 个单位扔向它的球越过；
- `none`：光地面，边缘只由砖条标出。

每道挡边和护栏都属于地面的物理：测试 `borders_and_railings_keep_the_ball_on_the_track`（ownlevels.rs）把每种球以每秒 12、25 和 40 个单位横向扔向 Parts_Test 的护栏和挡边并继续往里推，球都留在轨道上；慢慢偏进槽里的球会滚回来；从光地面扔出去的球会掉落。

**轨道的外观**和部件一样，按原版地面之所以好看的要素制作（在其地面和纹理上测得，只取数字）：一张纹理覆盖 5 个单位的地面；5×5 的石板，之间有接缝，每块有自己的色调、污迹和磨损，沿纹理排四块（20 个单位重复一次），每个关卡用三套石板中的一套；每侧边缘有一条路缘，带原版的小砖条、其凹槽和阴影；槽的斜面朝槽底变暗；挡边旁边有它投下的阴影；侧面是较暗的混凝土，带自己的砖条。纹理在 `assets/own/Track/`（make_textures.py 的 `track` 步骤）；挡边用菜单场景的砖。纹理按沿整条轨道的距离贴上，一段接一段铺设的轨道块（直的、弯的、宽度变化的一段）是同一个网格，因此纹理从一块到下一块没有接缝。

**没有接缝**（2026-11-03）：一段地面从起点或检查点到下一个是一个网格，其截面垂直于光标自身的朝向（在转弯处是精确的）沿路扫出，因此直道接弯道或坡道接平地时，在相接处截面完全相同：两者之间没有空楔；每一圈点都由其前后的四边形共享（没有裂缝，没有 T 形接点），纹理按沿路的距离贴图。起点和检查点的块也以同样方式连接：在地面延续的边上，其角点就是地面自身截面的点，其顶面按轨道的方式贴图。测试 `our_floors_have_no_seams`（ownlevels.rs）检查由工具包制作的每个关卡的地面（版本 2 起，见 level.gltf 的 `asset.generator`）：地面顶面结束之处，旁边在同一高度没有别的顶面（`the_seam_finder_sees_a_crack` 检查查找本身）。窄路上的检查点碗更小，深度也随之变小，坡度保持测得的值（停在更陡的碗里的石球滚不出来）。

**空间、轨道和云层**（2026-11-03，所有者试玩第 1 关之后）：道路在球心高度处必须给球（半径 2）留出至少 5.5 的宽度，在挡边之间或护栏横杆之间计算（levelkit.MIN_FREE）；工具包拒绝写出有更窄之处的关卡，并列出每一处（宽 6、带砖砌挡边的道路只留 4，球被卡住）。箱子或散落的球连同附近横在路上的东西，旁边也必须留出这么宽的空间，除非标记了 `shove`，且该处道路上的球（起点的球，之后为每个变换器的球）不比它轻（木 1.9、石 10、纸 0.2、箱子 1）；散落的球与轨道末端的距离不少于 14（它会滚进轨道的喇叭口）。轨道宽度按原版测得：管粗 0.6，两管中心相距 3.9，球深深坐在两管之间；我们的轨道平放在其离开的地面上（球落到轨道上下降 0.48），在末端接着地面的地方，每根管在地面的平坦部分上向外平弯，从上方看是一个喇叭口（槽形地面上没有：槽本身会把球引向中间）；管下的立柱支撑它们，两管之间的横枕只有在 `rails ... ties` 时才有，留给后面的关卡。变换器就放在它的球所要完成的任务之前。每种截面的平顶在相同的横向位置切分（距边缘 1、1.25 和 2.5，最后一处离中线至少 1.5，即窄槽形地面的槽底边），因此不同截面的路段首尾相接时共享顶点；每个面都朝向其法线所指的一侧（此前轨道的面绕向相反，法线朝内）。轨道的混凝土比原版的沙色更暗更灰，板缝更淡（所有者的意愿）。每个关卡下方都有一层与原版一样的云层（`SkyLayer`，在文件中隐藏，选项开启云层时由游戏显示，以叠加方式画在天空之上）：位于最低地面下方 165 处的平面，向四周超出关卡 500，我们自己的黑底灰云，每 675 重复一次。

**支撑、弯道和外观**（2026-11-03，所有者第三次查看）：轨道由几个托架托住，托架在两根管下方（低于在两管之间滚动的球），立在向下伸入雾霭的柱子上，大约每 40 一个，靠近两端（那里由地面支撑）和其他地面上方都不设；`railing turns` 从此处起在每个弯道的外侧设护栏（第 1 关如此），只在弯道内侧的护栏会被拒绝。云层只铺在云海类天空（A、B、C、Sunset）之下；第 1 关使用 `Mountains`。轨道侧面和柱子带有从上沿流下的雨痕，柱子分环浇筑（`Track_Column`）。部件的网格可以带一个更精细的外观（ownkit.py，`Mesh.look`：游戏绘制的样子，网格本身仍用于物理）：变换器画成原版那样的底座（围绕球材质圆盘的镀铬框、铆接底板上的彩色按钮），纸球画成揉皱的纸团，气球的绳子系在吊篮上。

**球的关卡门**（2026-11-03，在模拟中用长 20 的坡道测得）：木球和纸球从静止就能爬上 33 度的坡；石球从静止在 19 度停下，有 30 的助跑也在 24 度停下，所以在 20 的长度上升高 10（27 度）的坡道是只有木球（或纸球）能通过的门。第 1 关在每个木变换器之后紧接着设一道这样的门，并把石变换器放在需要石球的地方之前（散落的石球、箱子、空旷路段上的箱子、推杆）；长而空的直道被缩短并改成弯道。圆顶两侧都必须留出一条道路的空间（DSL 按该处地面的宽度检查，不满足就拒绝关卡）；箱子和散落的球也按同样的宽度检查。地面下和轨道下的柱子会按下方每段地面自身的宽度避开它。

**空气和需要解开的关卡门**（2026-11-03）：开放格式的关卡可以在设置中带雾（`fog`：朝地平线的 `color`、正下方的 `color_down`、每单位距离的 `density`，以及 `below`/`depth`：低于该高度的物体在该深度内完全融入雾中）。渲染器把雾画在所有受光照的物体上（天空、精灵和云层保持原色）；物理从不看到它，因此回放不变，原版关卡没有雾。我们的工具包从天空自身的颜色取雾色（地平线下方的雾霭、下方的世界），并让柱子和轨道支撑向下伸入雾中 240，使它们逐渐消失而不是突然中断；除 Night 外每种天空都有云层，即在其自身世界上方两层零散的云团。并非每次换球都在路线上：在第 1 关，石球来到一个它爬不上去的坡，木变换器在坡前小广场的一侧；木球来到一个推不动的箱子，石变换器在下方地面的一侧（快速的木球有时也能推动它）；每个需要某种球的分区仍然提供它。

**按所有者的概念图**（2026-11-03，他的图片只作参考）：轨道是磨旧的拉丝镀锌钢，带淡淡的锈色和起伏（`Track_Rail`，法线贴图），沿轨道每 9 有一个包住每根管的卡箍，其扣带在球的路径下方向下弯到另一根管，支撑处有一根细钢杆伸入雾霭（这些配件只用于绘制）；球画得很光滑（粗糙的网格仍用于物理）；起点立在伸入雾霭的石塔上；起点和每个检查点旁有木柱上的灯笼。

**部件立在平地上**（2026-11-03）：如果变换器底座、箱子或圆顶没有立在其底部平坦水平的一块地面上（按占地面积采样：其下每处地面顶面与底部相差不超过 0.05，且不缺失），工具包会拒绝该关卡并列出每一个；在它们所在之处，槽形地面会加宽或部件会移开。换球时球会蜕皮：碎片是它自身外壳的弯曲碎片，外面是它的纹理，里面是薄薄的内侧。

**散落物体躺在地面上，而不是嵌在里面**（2026-11-09）：部件的位置（`ahead`、`side`）是光标直线上、光标高度处的一个点，因此在斜坡之后、弯道旁或槽形地面的斜面上它并不在地面上：第 1 关有散落的球嵌入地面达 2.4 深，物理在其扇区开始时把每个球推出，碰到它的玩家球被以每秒数百单位的速度甩飞。现在工具包把每个散落的球放到其下方的东西上（从地面中抬出，或降到地面上；纸球按半径 2.04 的球体，即其外壳的范围），并拒绝散落的球或箱子在地面、轨道或挡块中开始深于 0.05、或散落的球悬空的关卡，并列出每一个（`levelkit.py --check 文件夹` 检查已生成的关卡）。放在斜坡上的球会被提示（它会在扇区开始时滚走）。游戏本身会在创建之前，把在静态几何体中开始深于 0.1 的散落物体抬到其表面上；原版关卡中没有深于 0.031 的（第 10 关的纸球），因此不会移动原版的任何物体。

**球上方的空间**（2026-11-03）：变换器（其笼子会抬起并夹住球）、风扇和气球上方 12 以内不得有任何地面或轨道；道路从其他地面或轨道下方穿过时，其底面离道路要么不超过 3.6（球撞上的一堵墙），要么 6 或更高（可通过），绝不能介于两者之间，否则球会卡住。工具包会拒绝违反其中任一条的关卡并列出位置。箱子可以叠放在另一个箱子上（`box ... up 5`）。

**几何检查**（2026-11-09，所有者试玩第 1 关之后）：工具包拒绝写出未通过三项检查（`levelcheck.py`）之一的关卡，并指出是什么、在哪里。*接缝：*两块地面相接处没有裂缝，也没有 0.005 到 0.05 的台阶（广场、圆盘、岔路、拐角恰好落在地面的高度；平块只在截面的平坦中间与截面相接）。*布景：*灯塔柱、旗杆、基座、花环、墙块和立柱不得位于地面顶面上方 5 以内（球的 4 加余量 1；侧面 0.3，轨道周围 2），除非描述中标记了 `obstacle`。*捷径：*路线上靠后 30 以上的地面，不得能从较前的地面通过坠落或从边缘飞出到达（球速 20、重力 20；实测最高速度：纸球 13.9、木球 15.9、石球 17.9；倾斜的块会加上升；带护栏或挡边的边缘不是起跳点），也不得从风扇顶部（地面上方 17）到达，除非描述中用 `drop [R]` 标出了落点。地面中的散落物体（`check_clear`）仍然不允许。

**起点和检查点**是碗形的，与原版一样（测得，只取数字）：起点是半径 10 的圆形平台，中间有半径 7.5、深 1.25 的碗（球停在碗里），边缘有四个火盆；检查点是一段长 10 的地面，其中下沉 1.26 的半径 5 的碗（到一圈边沿为止），以及横跨路线、位于两侧 ±7 处的两个火盆，部件的火焰就在那里燃烧。检查点前后的地面在它的地块处结束。它们的框架和复位点在碗中（复位点在碗底上方 3.65 和 3.33，与原版一样）。

**测试玩家对关卡的了解**也在同一个文件中。leveldsl.py 根据铺设的路线，把测试玩家三种风格的提示文件写入关卡的 `pilot/` 文件夹（autopilot.md，“提示文件”）：`safe`（从一点滚到另一点并停下，经过每个检查点，不冒险）、`speed`（不停顿地滚过各点）和 `collector`（同 safe，并去取路线外的每个额外分数和额外生命）。缺口、跷跷板和旋转臂在每种风格中都高速通过（谨慎的风格先助跑）；需要更多处理的地方用 `pilot STYLES : STEPS` 说明（提示的步骤，其点以相对光标的 `ahead side up` 表示；例如配合秋千时机的等待），并用 `nopilot STYLES` / `autopilot STYLES` 包住各风格能自行通过的路段。

**修改关卡**：编辑其 `level.lvl`，然后

```
scripts/own-levels.sh assets/levels/03_Paper_Winds
```

会构建关卡，并让测试玩家以每种风格游玩；每次到达终点的运行都保存为 `pilot/<style>.replay`（这些运行在 `target/` 下单独的数据文件夹中进行）。测试 `crates/game/src/ownlevels.rs` 在没有原版副本的情况下播放每个关卡的三次运行，任何一次未到达终点即失败，因此发布的关卡一定附有证明它能通关的运行。`scripts/video.sh assets/levels/03_Paper_Winds assets/levels/03_Paper_Winds/pilot/speed.replay out.mp4` 把一次运行渲染成视频。一个关卡大小为 3.3 到 3.8 MB，其中 2.6 MB 是它携带的纹理（该格式把关卡的纹理放在它自己的文件夹中）。

## 原版游戏：默认复制

游戏从玩家自己的副本中把所需内容一次性复制到 `levels/original/`：从已安装的游戏复制（`drahtseilakt --import <Ballance folder>`），或直接从游戏 CD 或其镜像复制（`drahtseilakt --import Ballance.cue`，也可以是 `.bin`、`.iso`：读取 `SETUP/` 中的 InstallShield 6 压缩包，由 `crates/cdimage` 实现）。副本是可选的（decisions.md，“游戏开箱即玩”）：没有副本时游戏以自己的关卡启动，主菜单的 **Import** 会打开一个窗口完成同样的事：它列出在电脑上找到的内容（Windows、Wine、GOG、Heroic 和 Lutris 常用文件夹中已安装的游戏；光驱中的光盘；主文件夹、桌面和“下载”文件夹中的 CD 镜像），接受拖到窗口上的文件夹或镜像或输入的路径，然后用这份副本启动游戏。副本是玩家自己机器上的玩家自己的数据；不下载任何东西，也不往仓库里放任何东西。`--data DIR` 仍可不经复制直接从任意文件夹游玩。

该文件夹的 README 列出了需要手动复制的内容：已安装的 Ballance 中的 `base.cmo` 以及 `3D Entities`、`Textures` 和 `Sounds` 文件夹（游戏不读取其他内容）；对于第 13 关，还需按其说明文件将 SuDu 扩展包安装到该副本中。

## 任何文件夹都可以移走

四个文件夹都可以在设置中指向别处（`levels.original`、`levels.community`、`levels.remastered`、`levels.open`），以便使用大容量磁盘或共享文件夹。此时默认文件夹中只保留一个 README，说明关卡在哪里，这样玩家去那里找时也能找到。

## 随游戏附带的内容

游戏安装时会在 `levels/open/` 中附带一些关卡（我们自己的），以及作者希望随游戏发布的转换后的自制地图。每个随附的关卡需要：

- 作者的许可和自由许可证，记录在关卡旁边（其文件夹中的 `LICENSE`）；
- 不含原版游戏的任何内容：不含 Ballance 的纹理、声音或网格。使用原版纹理的转换地图只写明纹理名称，游戏从 `levels/original/`（玩家的副本）中取用，就像该地图在原版中那样；
- 一个能通关的回放，按与原版关卡回放相同的方式检查。

只有在许可证允许后，仓库才会收录这类关卡；原版游戏的文件绝不会进入仓库。

## 每个文件夹都自带说明

首次启动时，游戏会在每个文件夹中用玩家的语言写入一个 README：这里该放什么、从哪里获取、关卡如何摆放，以及对于 `remastered/`，由哪个程序生成（工具箱）。旧版本写入且未被改动的 README 会被更新；玩家改过的保持不变。这些文本随游戏附带（各语言的文档）；README 中的链接只是文本，游戏从不打开它们。

## 按类别记录成绩和高分榜

回放、最佳时间和高分榜按类别分别保存，因此与原版关卡同名的自制地图绝不会被算作原版关卡：原版关卡为 `replays/<level>/`，其他为 `replays/maps/<kind>/<map>/`（`community`、`open`、`remastered`），关卡文件夹的为 `replays/levels/<kind>/<关卡文件夹>/<map>/`，这样两个文件夹中的 `Level_07.NMO` 不会共用成绩，单独的 `Foo.nmo` 和文件夹 `Foo/` 也不会。旧版本保存在 `replays/maps/<关卡文件夹>/` 中的成绩会在首次游玩该关卡时移到那里（只经过真实文件夹，绝不覆盖已有的成绩）。

社区规模最大的是中国（百度贴吧 平衡球吧、中文 Ballance 论坛、哔哩哔哩；见 community-maps.md），因此文档和各文件夹的 README 除英语、俄语和德语外，也提供简体中文版本。
