# 决定

这个分支为什么是现在这个样子。每一条：先写决定，再写理由。新的决定加在末尾；被取代的决定会标注出来，而不是删除。

## 分叉 OpenBallance，不重写

*2026-10-31 被下文的“一切从零开始，用 Rust 写”取代。*

上游代码是干净的 C11（约 2.7 万行），可移植的核心与宿主之间划分得很清楚：核心只依赖 `src/platform.h` 和
`src/render/gpu.h`，整个 gasm 绑定只有一个文件。它已经能运行原版的 Virtools 图，实现了游戏用到的约 180 个
Building Blocks，并移植了 Ipion 物理。难的部分已经完成；缺的东西（原生宿主、分辨率、第 13 关、地图）都建立在它之上。

## 引擎继续用 C

*2026-10-31 被下文的“语言为代码服务”取代。*

把能用的代码换一种语言重写，对玩家毫无益处，却要花上几个月。对我们的目标平台来说，C 也是可移植性最好的选择。

## 宿主用 SDL3，图形用 wgpu-native

*2026-10-31 被下文的“一切从零开始，用 Rust 写”取代（图形仍用 wgpu，改用其 Rust 库）。*

SDL3 是 Linux、Windows 和 macOS 上窗口、输入、手柄和音频的事实标准，各发行版都有打包。wgpu-native 是以原生库形式
提供、带 C API 的 WebGPU，运行在 Vulkan、Metal 和 Direct3D 12 之上；渲染器本来就使用 WebGPU 和 WGSL，所以几乎可以原样迁移。

## 两种关卡格式并存，永久并存

引擎读取原版的 `.nmo` / `.cmo`，以后还会读取我们自己的开放格式。对 `.nmo` 的支持不是过渡性的：大约 425 张自制地图
只有这种格式，其中许多带有自己的脚本。开放格式用于编辑和制作关卡。同一关卡的原始版本和转换版本同时也是对转换器的测试。

## 仓库里不放游戏数据，放大过的也不行

*2026-10-31 修订：见下文“私有仓库是备份”。*

Ballance 的版权并没有随着 Cyparade 消失：这款游戏于 2024 年 1 月在 Steam 上重新发行（Ziggurat Interactive），
GOG 上也有售。原版资源以及由它们派生的任何东西（放大的、修饰过的）都不进入仓库。除了法律问题之外，GitHub 上的
一份 DMCA 通知会让整个仓库被禁用，而不只是一个文件夹。更高分辨率的纹理来自一条可复现的流水线，在玩家自己的副本上运行。

仓库目前（2026-10-30）是私有的，这在开发期间消除了被下架的风险；这条规则仍然保留，因为代码是要公开的。

## 公开发行版有自己的内容

*2026-10-31 被下文的“游戏只运行玩家自己的数据”取代。*

面向所有人的发行版会附带新制作的纹理和关卡——按照原版的精神重新绘制，而不是从它的像素派生——在玩家拥有副本时则使用
原版游戏的数据（Freedoom 模式）。修饰原版纹理并不能让它们变成我们的。

## 固定 60 Hz 模拟，插值渲染

物理和每一张自制地图都是按原版的 60 Hz 步长调校的。模拟始终以 60 Hz 运行；只有绘制跟随显示器，在两个 tick 之间插值。
可变步长会改变球的行为，并破坏地图。

## 球用解析方式绘制

用光线求交逐像素绘制的球体在任何分辨率下都是圆的，网格永远做不到。用球体方式绘制的对象集合来自数据，所以这是渲染器的
一项功能，而不是特例。

## 安全规则适用于一切

项目所有者的安全代码生成规则（https://github.com/eugene-vereshchagin/secure-codegen-rules）约束所有代码。重点在解析器上：
自制地图是来自陌生人的不可信文件，所以 `.nmo` 读取器要经过模糊测试，并且出错时一律拒绝（fail closed）。

## 工作流程

开发由项目所有者机器上（那里有游戏数据）的本地代理进行；改动在那里测试过之后才进入 git。CI 按需运行，并在 pull request
上运行。没有项目所有者的明确指令，不发行、不打标签、不公开任何东西。

## 名字

*Drahtseilakt* 在德语中意为走钢丝，引申为任何一步踏错就会坠落的平衡之举——在深渊上方沿着轨道滚球正是如此。用德语是向
Cyparade 致意，它是制作 Ballance 的德国工作室。

文档用英语和俄语编写。英语是主版本（它是代码、注释和提交信息所用的语言）；俄语版在 `docs/ru/` 和 `README.ru.md` 中镜像其

文档用英语、俄语、德语和简体中文编写（简体中文于 2026-11-02 为庞大的中文社区加入）。英语是主版本（代码、注释和提交信息所用的语言）；其他语言在 `docs/<lang>/` 和 `README.<lang>.md`

## 视觉平滑绝不触及物理

让弯曲的几何体看起来圆滑（第 3 阶段）纯粹是渲染问题。碰撞几何体严格保持原版的样子，因为球的行为和每一张自制地图都是按它调校的。
用哪些平滑技术，要试过之后再定；这条约束则不变。

## 游戏可玩之前，仓库保持私有

在所有原版关卡（十二关加第 13 关）都能原生游玩之前，不公开展示任何东西——仓库、网站、视频都不。不展示半成品代码。
公开与否由项目所有者下令，和任何发行一样。

## 游戏永不联网

完成的游戏不建立任何网络连接：启动时和游玩时都不下载任何东西——不按需下载字体、着色器或其他资源，不检查更新，没有遥测。
它需要的一切都随游戏附带（包括字体及其许可证），或者来自玩家自己的 Ballance 副本。自制地图和模组是玩家自己放进去的文件；
游戏不会去获取它们。构建时的依赖是另一回事：构建可以下载它们，版本固定并校验校验和，同时也必须能离线使用本地副本完成构建。

## 游戏只运行玩家自己的数据

取代“公开发行版有自己的内容”。我们不制作替代内容：游戏运行的是玩家自己的 Ballance 副本中的数据，原版关卡和自制地图都一样。
对这些数据的改进——例如放大到 4K 的纹理——来自玩家在自己的副本上本地运行的脚本；结果留在玩家的机器上，我们从不分发。

## 原生关卡和原版 `.nmo` 都能玩

游戏是新的，有自己的关卡格式；地图会被转换成这种格式。玩家仍然可以原样游玩任何 `.nmo`——十二关、第 13 关以及每一张自制地图——
因此转换失败或效果不佳时，也不会让任何人失去一张地图。这既照顾了想要原汁原味的人，也照顾了想要新东西的人。它强化了
“两种关卡格式并存，永久并存”：两种格式都能玩，而不只是能读取。

## 私有仓库是备份；公开仓库从干净状态开始

在仓库私有期间，它可以存放工作所需的任何东西，包括原版关卡和其他游戏数据，作为备份。公开发行的永远不是这个仓库：而是一个新仓库，
从清理过的、不带这段历史的目录树创建，在第一次推送前检查其中有没有游戏数据。在此之前，“仓库里不放游戏数据”这条规则仍然适用于
所有打算公开的东西：代码、测试和文档都不依赖仓库里有游戏数据。

## 不做浏览器版本

浏览器（gasm/WebAssembly）版本是随上游带来的，不是本项目的目标。它不再是目标平台：任何改动都不必保证它能构建，它所依赖的代码
被替换时它就会被移除。目标平台是原生的 Linux、Windows 和 macOS。

## 语言为代码服务

*2026-10-31 被下文的“一切从零开始，用 Rust 写”取代。*

取代“引擎继续用 C”。C 和 C++ 都可以——我们所依托的代码用什么写就用什么，怎样能让源码清晰就怎样。重要的是一切都以源码形式存在、
项目井然有序，而不是语言本身。

## 一切从零开始，用 Rust 写

结束第 0 阶段，并取代“分叉 OpenBallance，不重写”、“宿主用 SDL3，图形用 wgpu-native”和“语言为代码服务”。引擎、游戏、转换器和
工具全部重新编写，不采用其他项目的任何代码。

原因是来源问题。Ballanced 的物理是从 Source 引擎泄露出来的 Ipion 源码（“All rights reserved”，没有许可证），它还有两个模块根本
没有许可证；OpenBallance 的物理则是从我们自己对原版 DLL 的反编译移植而来。拿来其中的部分，就要继承这些问题，而把代码翻译成另一种
语言并不能解决它们：翻译是衍生作品。从零编写，每一行都有清楚的来源。

为什么用 Rust：引擎的主要风险是恶意输入（来自陌生人文件分享的自制地图），而用安全 Rust 写的解析器不会越界读取，也不会破坏内存——
这一整类 bug，否则只能靠安全规则手工去防。wgpu（Vulkan、Metal、Direct3D 12）是它的原生生态，cargo 则在三个平台上都提供
版本固定、依赖内置（vendored）、可离线的构建以及模糊测试。

## 物理移植自 OpenBallance（GPL-3.0）

就球和关卡中的物体而言，取代“刚体物理来自一个库：rapier”。OpenBallance 的物理（`src/phys`，约 9,600 行 C）是原版游戏
`physics_RT.dll` 的移植，基于我们自己的反编译（`docs/physics.md`）编写，而且该项目和我们一样是 GPL-3.0。把它移植到 Rust 是 GPL
允许的衍生作品：我们保留上游作者的版权声明和许可证，在每个移植的文件上标明来源，并在 README 中致谢 OpenBallance。它是开源代码中
最接近原版手感的东西，能为我们省下几个月的手工调校。

这并不是对 Ballanced 的例外。它的物理是泄露的 Ipion 源码（“All rights reserved”），不以任何语言使用。rapier 只作为对比测试台保留，
直到移植版与原版一致为止。

## 刚体物理来自一个库：rapier

取代物理全部手写的规则。我们自己的箱子和球的求解器会让箱子下沉、互相穿过、丢失；一个现成的、经过测试的刚体引擎能把这些做好。
我们依赖 rapier3d 0.36（Apache-2.0，与 GPL-3.0 兼容，由 dimforge 维护），就像依赖 wgpu 和 winit 一样：这是一个库，而不是从另一个
游戏项目拿来的代码。我们负责的是游戏本身的部分：关卡作为一个静态网格、原版游戏的材质数值（成对的摩擦和弹性取乘积，
docs/physics.md 第 3、4 节）、玩家的控制冲量，以及每个 tick 一步，以便回放能够复现。

## 其他项目是参考和测试台

OpenBallance、Ballanced 和在 Wine 下运行的原版游戏用于研究行为和对比：运行它们、阅读它们的文档、测量它们。不从它们复制任何代码。
泄露的 Ipion 源码根本不打开：物理是根据原版游戏实测的行为构建的。`docs/` 中的逆向工程笔记（文件格式、Building Blocks、游戏的行为）
作为参考保留。

## 声音通过 cpal 输出

*2026-11-01。* 游戏通过 cpal 0.18（Apache-2.0，RustAudio）播放玩家的 WAV 文件：Linux 上用 ALSA（PipeWire 和 PulseAudio 通过各自的
ALSA 层接管；构建需要 ALSA 头文件，Debian 上是 `libasound2-dev`），Windows 上用 WASAPI，macOS 上用 CoreAudio。它只负责打开一个输出流；
读取 WAV、混音、音量和音高都由我们自己实现（crates/game/src/audio.rs），这让我们贴近原版声音脚本的做法。rodio 和 kira 带有我们不需要的
解码器和混音器；miniaudio、SDL3 和 OpenAL 是 C 库。这个 crate 版本固定，源码放在 cargo 缓存中，所以构建仍然是离线的。

## 关卡放在一个文件夹里，分四类

*2026-11-02。* 所有关卡都放在游戏数据文件夹的 `levels/` 中，按来源和格式分成四个文件夹：`original/`（玩家的原版游戏副本，默认复制到这里）、
`community/`（`.nmo` 自制地图）、`remastered/`（转换为开放格式并配上现代纹理的原版关卡，在玩家的机器上生成）和 `open/`（开放格式的关卡，
自己制作的或转换而来的）。其中任何一个都可以在设置中移到别处；默认文件夹里随后会留一个 README，说明它们去了哪里。经典模式只能看到原版。
有些开放格式的关卡会随游戏附带，前提是作者愿意，采用自由许可证，并且其中不含原版的任何资源。社区在中国最大，所以文档也有简体中文版。
详情：[levels.md](levels.md)。


## 随游戏提供的关卡是新内容

*2026-11-02.* “游戏只使用玩家自己的数据”这一规则禁止替换原版的文件。作者允许随游戏提供、采用自由许可证且不含任何原版资源的关卡属于新内容，可以随游戏提供（levels.md）。玩家自己复制到其文件夹中的内容是他们自己的事，与我们无关。


## 关卡由 toolbox 准备，游戏只负责游玩

*2026-11-02.* 重制关卡由一个独立程序 `drahtseilakt-toolbox` 生成，它有自己的仓库
（eugene-vereshchagin/drahtseilakt-toolbox，与本仓库并列），作为独立程序展示和发布；它通过以路径引用的本仓库 `crates/gamedata` 和 `crates/level` 与游戏共用关卡读取代码。游戏游玩原版 `.nmo` 文件和其文件夹中的开放格式关卡，
不关心它们是如何制作的；游戏从不运行其他程序。toolbox 把原版关卡转换到 `levels/remastered/`，把每个弯曲网格更圆的外观写入关卡
（开放格式把它保存在网格旁边，物理仍使用网格本身，因此通关过程不变），并放大纹理。能补出细节的 Real-ESRGAN 只有在玩家自行安装后才会使用；
它从不被下载，也从不是游戏的依赖，因此普通玩家除了游戏之外什么都不需要。toolbox 的压缩包以后是否附带 Real-ESRGAN
（其许可证允许，版本固定并校验），在发布时决定。


## 默认使用自有内容，按玩家意愿使用原版内容

*2026-11-02.* 取代“游戏只运行玩家自己的数据，不提供替代内容”。游戏随附自己的界面和部件（菜单、字体、界面音效、球、关卡需要的模块），由我们尽力做得接近原版：自己绘制的图像和音效、自由许可的字体，不含任何原版内容。在扩展模式中，一个开关可改为使用玩家拷贝中的原版内容，或由 toolbox 制作的原版重制。关卡有两种分享方式：附带自由许可的自有资源；或者，为想要原版外观的玩家，关卡只引用原版资源，由 toolbox 从每位玩家自己的拷贝中补上。toolbox 能从玩家的原版文件中制作游戏可用的全部资源。这样不会分发任何人的财产，每个人点几下就能在自己电脑上组装出原版。

## 自有界面为默认

*2026-11-03.* 依据“默认使用自有内容”，游戏自带自己的界面（菜单、关卡内界面、关卡结束和加载画面：由仓库中的脚本绘制的我们自己的纹理、自由授权的 Tektur 字体、我们自己的文字），这是每位玩家默认看到的界面，经典模式下始终如此。扩展模式的 Interface 开关可以选择来自玩家拷贝的原版界面或其重制版。自有菜单支持七种语言（英语、俄语、德语、简体中文、法语、西班牙语、意大利语）：Options 中的 Language 页面，经典模式下也有，因为看不懂菜单的玩家就无法游戏；默认使用系统语言，否则使用英语。使用原版界面且选择了拷贝没有的语言（俄语、中文）时，我们的文字用随附字体绘制，因为拷贝的字体只有 Latin-1。选择 Tektur 而不是 Michroma（更接近原版的宽体字母，但只有拉丁字母），是为了让所有拉丁和西里尔文字保持同一种设计。

## 生成的音效主题为默认

*2026-11-02.* 项目所有者的决定：生成的音效主题（*neuro*：由代码合成、依据对原版音效的测量调校的音效，其中不含任何原版内容）作为游戏的默认音效主题随附。在玩家于 Extended 页面选择其他主题之前，它都会播放；经典模式下始终播放它。*system* 仍是所有主题的后备主题，并且仍可选择，*original* 和玩家自己的主题也一样。玩家做出的选择会被保留；只有在玩家做出选择之后，设置才会写入 `sound-theme`，因此从未选择过的玩家会跟随默认主题。

## 一个关卡就是一个文件夹

*2026-11-03，所有者的决定。* 自定义关卡菜单过去会显示 `levels/community/` 里的一切：解压出来的层层文件夹、图片、文档、压缩包。现在一个关卡是类别文件夹中直接的一个文件夹，其中恰好有一个关卡：一个 `.nmo` 或一个开放格式关卡（清晰的格式，便于手工完成或修改），可选 `level.txt`（标题、作者、版本）、README、预览图以及它使用的资源文件夹；其他一切和更深的嵌套都被忽略，没有关卡或有多个关卡的文件夹不算关卡。类别文件夹中单独的 `.nmo` 也是一个关卡，最简单的放法。玩家可以在 level.txt 中给关卡命名，但标题会被清理并截断到 40 个字符（按单词，“…”），在菜单和游戏显示名称的所有地方都是如此，因此标题绝不会撑破界面。菜单是按标题排序的扁平列表。没有“合集”这一概念：一个系列变成每关一个文件夹。`drahtseilakt-toolbox import-maps` 把下载内容整理成这种结构。详见 [levels.md](levels.md)，“一个关卡就是一个文件夹”。

## 在自有界面重做期间默认使用拷贝的界面

2026-11-03，所有者：第一版自有界面（紫色胶囊按钮、绘制的背景）与原版毫无相似之处。在重做的版本令人满意之前，默认（以及经典
模式）使用玩家拷贝自带的界面（若拷贝有其菜单），否则使用我们的。这样不会分发任何原版内容：它来自玩家自己的拷贝，和关卡一样。
界面不再决定音效主题。

## 游戏开箱即玩

*2026-11-03，所有者为发布设定的条件。* 原版关卡的布局及其部件模型（`3D Entities/PH/*.nmo`、`Balls.nmo` 等）是
Cyparade 和 Atari 的作品；玩法机制是自由的。因此在发布之前，游戏需要自己的部件和自己的关卡，并且必须在任何人导入
任何东西*之前*就能正常运行：完全没有原版副本时也能启动和游玩。没有副本时，菜单提供我们自己的关卡（随游戏附带的和
`levels/open/` 中的）以及导入副本；一局游戏所需的一切（界面、声音、字体、菜单场景、球及其碎片、模块、天空、粒子、
球的影子、默认按键、关卡设置）都来自游戏自带的文件。我们的部件由 `assets/own/make` 中的脚本按原版测得的尺寸制作，
物理参数保持不变，因此行为与原版相同；不复制原版的任何几何数据。发布标准见 [roadmap.md](roadmap.md)「发布标准」。

## 默认使用自有纹理

2026-11-03，所有者的决定：我们自己的关卡、关卡部件和球的纹理（由仓库中的脚本用 CC0 照片纹理制作，按原版实测的调色板、颗粒和布局调整；不含任何原版内容）是每个关卡默认使用的纹理，经典模式下始终如此；扩展页面的“纹理”开关（`textures original`）改用拷贝的纹理。所有者决定不逐一审阅就直接采用：不满意的以后再替换。我们的纹理按原版纹理名称替换，无论哪个关卡请求它（原版关卡、社区地图、部件）；我们没有的纹理（天空、粒子、光晕、阴影、少数图片）仍取自拷贝。开放格式关卡自带的纹理仍归其作者。用 `--textures own` 导出关卡会写入我们的纹理，因此只用自由资源即可分享。（审查后细化：他人地图中只替换拷贝自己的纹理，绝不替换地图自己的图片；拷贝关卡的重制版与拷贝关卡一样替换；菜单场景跟随界面。）

## 纹理包与模型包

2026-11-03，所有者的要求：关卡的外观来自玩家选择的包，就像声音来自主题一样（[packs.md](packs.md)）：纹理包（内置：`own`、`original`、`remastered`）和模型包（内置：`level`、`own`、`original`），各在扩展页面上占一行；玩家放进数据文件夹 `textures/` 或 `models/` 的任何文件夹都会成为新的包。包只替换它拥有的内容；它缺少的来自它的后备，再来自默认。模型包只改变绘制的网格：物理始终使用实测的形状（拷贝关卡用原版的，我们的关卡用我们的），因此玩法和回放绝不会改变。我们自己的关卡以游戏纹理名称引用共用的纹理（`game:` 图片，open-format.md），不再携带副本，因此纹理包也会改变它们，每个关卡的大小约减半。经典模式保持不变：我们的纹理，每个关卡自己采用的部件。`original` 现在在重制关卡中也表示拷贝的图片；重制版自己的放大图片是 `remastered`。

## 我们自己的纯数据模组格式

2026-11-03，所有者的决定：游戏有模组——每个玩家可以打开或关闭的行为和功能增补——采用我们自己的格式，而且这些功能本身就是模组：游戏附带*内置模组*（`assets/mods/`），用玩家所用的同一格式编写，同时作为示例（[mods.md](mods.md)）。模组是数据：一个由规则（`on <event>`、`if <condition>`、`do <action>`）组成的 mod.txt，基于引擎构件的固定库，带有选项、标签、变量和小型的全函数表达式，由我们的运行时解释，就像原版的行为图由它的运行时解释一样。模组中的任何东西都不会作为代码运行：没有脚本、没有路径、没有链接、没有资源；模组文件夹只包含一个 mod.txt，最多再加一个 readme 和一个许可证，其他任何东西都会导致拒绝该模组。陌生人的模组是恶意输入：严格解析，每个数量都有上限，错误会指出所在行。基于游玩事件的规则只读取游玩本身，并且只有它们可以改变游玩，因此游玩保持确定性；改变游玩的模组会把它标记为 modded，其回放会以哈希和选项写明该模组（永远不算最佳成绩，永远不进高分榜；经典游玩及其回放不变）。音效主题、纹理包和模型包以及关卡都不是模组：它们保留各自的菜单。BML mod 是 Windows DLL：它们作为需求被静态调查过，但永远不会被加载、运行或导入——即使在 Wine 下也不会。

## 上帝模式是一个开发用模组

*2026-11-03，所有者的决定*（“我们的调试工具应该变成一个特殊的模组，上帝模式，带有自由存档、无限生命和后退；我们也许根本不把它随主游戏发布，这样游戏更有意思”）。扩展模式的练习工具（保存和读取当前时刻、后退几秒、减速和加速、自由相机、重新开始、屏幕上的小节和 tick）以及无限生命不再是游戏本身的附加功能：它们合成一个模组 `god-mode`，用我们的纯数据模组格式编写，所用的构件是该格式为它新增的（`lives.endless`、`rewind`、`save`、`load`、`slower`、`faster`、`freecam`、`keys`），因此它的按键是其页面上的选项，开启时显示在屏幕上。它是一个*开发用模组*：放在 `assets/mods-dev/` 中，只有以 `--debug` 启动的游玩才会读取，发布包不包含该文件夹。“All levels open”同样只属于调试运行；玩家的游戏通过游玩来解锁关卡。上帝模式的游玩会改变游玩，因此是 modded：会被保存，但不解锁任何关卡，永远不算最佳成绩或高分，其回放会写明该模组。详见 [mods.md](mods.md)，“上帝模式”。

## 关卡按难度列出，使用英文标题

*2026-11-03，所有者的决定*（“把自定义关卡整理成一种格式，别让它成为一堆杂物”）。关卡的 level.txt 给出其 `difficulty`，一个 1 到 10 的整数（其他任何值都视为未知），以及英文的 `title`，其他语言中的名称写作 `title.<代码>`。菜单显示每个关卡的难度和标题，并按难度、其次按标题排序；难度未知的关卡排在其后，没有标题（以文件夹命名）的关卡排在最后。我们的十个关卡评为 1 到 10。toolbox 根据社区的目录填写 level.txt（英文名称、原名、作者、目录中 1–5 的难度乘以二），而既不在目录中也没有附带 readme 的地图、以及不是单个关卡的压缩包和文件夹，会被放到 `levels/community-unsorted/` 中供玩家手工查看，不会被列出。给作者和玩家的规则集中在一页：[making-levels.md](making-levels.md)。

## 经典模式提供外观选择

*2026-11-09，所有者的决定。* 原先只属于扩展模式的外观选择，经典模式也提供：Graphics 页的 *Textures* 和 *Models*，Sound 页的 *Sound theme*（先是原版的各行，顺序不变，我们的在其下，如同 *Fullscreen?*），设置键相同（`textures`、`models`、`sound-theme`）。找到的每个包都会出现：内置的 `own`、`original`（仅当玩家的副本存在时）、`remastered`，以及数据文件夹中的任何包，因此玩家自己转换的资源会直接出现在选项中。默认值不变（我们的纹理、关卡自带的部件、默认主题）。玩法和规则仍是原版的，回放不依赖外观。渲染修正（任意分辨率、宽屏、过滤、平滑）始终开启，不可切换。这取代了此前“经典模式始终使用我们的纹理和关卡自带的部件、始终播放默认主题”的说明。

## 按含义划分的 Start

*所有者的决定，2026-11-09。* Start 不再按文件夹显示关卡（Original、Remastered、Open format、Modified originals、
Community picks、My maps），而是按含义，在经典和扩展模式下相同；为空或不可用的项目不显示：*经典 Ballance*（玩家副本的
13 个原版关卡）、*Drahtseilakt*（我们自己的 13 个关卡）、*Ballance 挑战*（社区对原版的改造，原称“修改版原版”；需要副本）
和 *社区地图*（子菜单：*精选*，随游戏附带的 13 张地图及作者；*已下载*，玩家的文件夹）。玩家的文件夹是
`levels/downloaded/`，容纳 `.nmo` 地图和开放格式关卡；`levels/community/` 和 `levels/open/` 仍会读取且不会被移动，成绩的键
随关卡所在文件夹而定，因此已有成绩保留。*Remastered* 离开 Start：它成为 Options 中的 *外观：原版 / 重制版* 一行（仅在有导出时
显示），是设置而非关卡类别；第二阶段会把重制变成纹理包和模型包。
