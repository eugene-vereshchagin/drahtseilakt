# 开放关卡格式（版本 1）

引擎自己的关卡格式：开放、有文档、可用普通工具编辑。游戏能加载的每个关卡——玩家副本中的原版关卡、自制地图——都在玩家的机器上转换成这种格式（`drahtseilakt --level N --export DIR`、`--map FILE --export DIR`），游戏再加以游玩（`drahtseilakt --open DIR`）。转换后的关卡由玩家自己的数据生成，不对外分发。使用 `--textures own` 导出时，凡是我们有对应纹理的地方都写入我们的自由纹理（resources.md，“自有纹理”）而不是拷贝的纹理，这样关卡的外观只用自由资源即可分享。内容相同的纹理图片只写一次，由各材质共用；未找到的纹理会在摘要中按名称列出。使用 `--textures own` 时也不写 `game/` 文件夹（不含拷贝的任何内容：关卡使用游戏自己的部件和声音）；`--export-parts keep|none` 可明确指定。

## 文件

一个文件夹，包含：

- `level.gltf` —— [glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)（JSON）；
- `level.bin` —— 其二进制缓冲区（唯一的缓冲区，按此名称引用）；
- `textures/NNNN_name.png` —— 每个纹理一张图片；图片的 `uri` 必须直接指向 `textures/` 中的普通文件（不能有更深的文件夹），或者是 `game:<名称>`，否则关卡会被拒绝。`game:<名称>` 引用的不是文件，而是**游戏中该名称的纹理**：不为它读取任何文件；游戏用所选纹理包绘制它（[packs.md](packs.md)）：先找关卡自己 `game/Textures/` 中该名称的图片，再找纹理包及其后备，再找我们的，最后找拷贝的（名称按纹理名称比较：忽略大小写、`_`、`-`、空格和扩展名）。名称长 1 到 128 个字符，不含 `/`、`\`、`:` 或控制字符，且不以点开头；它只与纹理名称比较，绝不会构成路径。我们的关卡用这种方式引用共用的纹理（轨道侧面、边框砖、木材、栏杆、立柱、检查点地板），所以纹理包也会改变它们；它们自己的特殊纹理仍以文件保存。`--export` 原样保留 `game:` 图片。以前制作的关卡照常可用：它们的文件仍是它们自己的；
- `level.txt`（可选）——以 `键 = 值` 行写出标题、作者和版本；`levels/` 中的关卡是只含一个关卡的文件夹，以此标题命名（[levels.md](levels.md)，“一个关卡就是一个文件夹”）；
- `game/` —— 关卡使用的游戏文件，按其在玩家拷贝中的路径存放，使关卡无需拷贝中的关卡文件也能游玩：它的部件采用同样的开放格式，每个部件是一个以文件名（去掉 `.nmo`）命名的文件夹（`game/3D Entities/Balls/`、`game/3D Entities/AnimTrafo/`、`game/3D Entities/PH/P_Box/`……：球、变球器以及每个以其命名的对象所对应的模块），另外原样存放其天空的各面（`game/Textures/Sky/`）、粒子纹理（`game/Textures/Particles/`）、球的阴影以及一次游玩会播放的声音（`game/Sounds/`，不含菜单声音和其他关卡的音乐）。游戏先在那里查找；对于为我们自己的部件而做的关卡（其设置写有 `"parts": "own"`），接着到我们自己的部件（`assets/own/`，[resources.md](resources.md)）中、再到拷贝中查找，因此有没有拷贝都玩起来一样；对于其他任何关卡，接着到拷贝中、再到我们的部件中查找。`game/` 中路径上任何一环是链接时都找不到文件。`game/` 只能替代关卡自己的部件、天空、粒子、阴影和一次游玩的声音，界面文件（菜单、字体、关卡表、菜单声音）从不来自关卡：它们属于界面（我们自己的，或拷贝的），每个文件的读取都有大小上限。任何关卡都可以声明任意 `sector_balls`（列表，第 1 段在前，取值 `wood`、`stone`、`paper`、`sticky` 或 null：用 `--sector` 从该分段开始时的球；缺省为关卡的起始球）、`source_hash`，因此能在其上播放的回放并不能证明在原版上完成过游玩。没有设置的关卡（在开始保存设置之前制作的）使用默认值并给出提示；重制的 `Level_NN` 则从拷贝的表中获取设置。`--export` 和 toolbox 会写入它。

## 压缩纹理

在大图片 `textures/NNNN_name.png` 旁边，关卡可以带有 `textures/NNNN_name.dtx`：同一张图片，已为显卡准备好——块压缩，并预先做好
整条 mip 链。这样加载关卡时游戏既不解码 PNG 也不计算 mip，纹理只占显存的八分之一（BC1）或四分之一（BC7）。toolbox 的 `remaster`
会写出它们（512 x 512 及以上、边长为 4 的倍数的图片）；关卡文件并不提及它们。关卡在 `game/` 中的部件同样带有自己的。

文件（小端序），`crates/gamedata/src/gputex.rs`：

| 字节 | 内容 |
|---|---|
| 0–3 | `DSTX` |
| 4–5 | 版本，1 |
| 6 | 格式：1 = BC1（不透明颜色，每像素 4 位），2 = BC7（带 alpha，或带高度的法线贴图；每像素 8 位） |
| 7 | mip 级数：总是直到 1 x 1 的整条链 |
| 8–11、12–15 | 宽、高：4 的倍数，最大 4096 |
| 16–23、24–31 | 它所源自的图片文件：长度和哈希 |
| 32–39 | 其后数据的哈希 |
| 40– | 各 mip 级的块，最大的在前，之后没有任何内容 |

哈希是对 8 字节小端序字做的 FNV-1a（末尾补零），再加上长度。BC1 块为四色模式（第一个颜色较大）或单色；BC7 块为模式 6。纹理不是
sRGB（游戏和原版一样在伽马空间中计算光照）。

该文件和关卡的其余部分一样来自陌生人：在读取任何内容之前先按上限检查文件头，长度必须恰好是文件头所决定的，数据必须与哈希相符且只
含上述的块，并且绝不跟随链接。所记图片长度与旁边 PNG 不同的文件，或文件头不通过的文件，会被跳过而使用 PNG；数据损坏的文件，或在查看与读取之间被改动的文件，会给出提示并改为绘制缩小的 PNG（请重新 remaster 该关卡）。经由指向关卡文件夹之外的链接到达的文件会被拒绝。关卡也可以只带 `.dtx` 而没有 PNG。

- **适配器。** Vulkan 和 Direct3D 12 下的所有桌面显卡以及 Metal 下的所有 Mac 都支持 BC。在不支持的地方（某些手机芯片、某些软件
  适配器），游戏自己解码这些块，从边长不超过 1024 的 mip 级开始。已在 Linux（Vulkan，NVIDIA）上以两种方式检验；Windows 和 macOS
  未运行。
- **内存。** 关卡自己的游戏文件（`game/`）共享 1 GiB 纹理内存的预算；一个纹理最多占用剩余部分的八分之一——更大的纹理会去掉最大的
  几级 mip 来绘制（PNG 则减半），绝不会画成空白。多个部件所带的同一张图片（相同数据）只上传并计数一次。
- **加载。** 纹理每次读取八个，各在自己的线程中，读好即上传。游戏会打印上传的数量、它们的显存和时间。

## 内容

- **节点（Nodes）**：关卡中每个对象一个，按顺序排列，带有名称、世界 `matrix`，若需绘制还带有 `mesh`。`extras.drahtseilakt.visible` 表示该对象是否显示；`extras.drahtseilakt.parent` 是脚本移动某节点时该对象跟随的那个节点的索引（地图中的 Set Parent；矩阵仍是世界矩阵，因此它不是 glTF 子节点；不指向另一个节点的索引会使关卡被拒绝，循环会被打断）。含有非有限元素的矩阵（地图中会有，游戏照样运行）完整保存在 `extras.drahtseilakt.matrix` 中，这些元素写作 `"nan"`、`"inf"` 或 `"-inf"`；glTF 的 `matrix` 中对应位置为 0。
- **网格（Meshes）**：每个有顶点的网格一个；每种材质一个图元，同一网格的所有图元共用相同的 `POSITION`、`NORMAL` 和 `TEXCOORD_0` 访问器（浮点），`indices` 为 32 位整数。只有顶点没有面的网格（地图粒子的发射点）是一个 `mode` 为 0（点）的图元，不带 `indices` 和 `material`。网格的材质通道（用另一材质对整个网格再绘制一遍）位于 `extras.drahtseilakt.channels`：每个通道包含其 `material`、`blend`（源与目标因子名，见下文）和 `texcoord` k，即存放其坐标的 `TEXCOORD_k` 集；最多 16 个。网格可以带一个更精细的外观，绘制时代替它（`extras.drahtseilakt.look`：另一个网格的索引；toolbox 用它保存更圆的形状）：这些网格排在关卡自身所有网格之后，每个只作为一个网格的外观，节点从不放置它们；物理和规则使用网格本身。
- **材质（Materials）**：`baseColorFactor`（漫反射）、`baseColorTexture`、`normalTexture`（切线空间的法线贴图，与 glTF 一样绿色朝上：toolbox 为重制关卡生成的凹凸细节；必须指向关卡的某个纹理；带有 `extras.drahtseilakt.parallax`（以纹理坐标计的深度，大于 0 且不超过 0.25）时，其 alpha 通道是高度，1 为顶部，渲染器以视差绘制，使凹凸在掠射视角下仍保持深度）、`emissiveFactor`、`doubleSided`；`alphaMode` 为 `OPAQUE`、`MASK`（带 `alphaCutoff`）或 `BLEND`；无光照材质使用 `KHR_materials_unlit`。
  `extras.drahtseilakt` 存放 glTF 没有对应字段的内容：`ambient`、`specular` 与 `power`（高光）、`z_write`、`blend`（源与目标因子名：`zero`、`one`、`src_color`、`inv_src_color`、`src_alpha`、`inv_src_alpha`、`dest_alpha`、`inv_dest_alpha`、`dest_color`、`inv_dest_color`）、混合与 alpha 测试同时使用时的 `alpha_cutoff`，以及纹理坐标由视角生成时的 `texgen`（`reflect` 或 `chrome`）。
- **场景附加数据** `extras.drahtseilakt`：`format`（1）、`groups`（名称和成员节点索引——游戏规则读取这些，见 [nmo-format.md](nmo-format.md)）、`sky`（天空字母）、`start_ball` 和 `settings`：原版从其关卡表和按关卡编号的规则中获取的内容，使关卡在没有游戏文件时也能同样游玩——`music`（主题 1 到 1000）、`light`（三个 0..1 的数）、`level_bonus`（分数）、`tutorial` 和 `last_level`（true 或 false：原版的第一关和最后一关），以及 `source_hash`（16 位十六进制：转换来源 `.nmo` 的 FNV-1a）以及 `parts`（`"own"`：关卡为游戏自己的部件而做，优先于拷贝的部件使用它们；`"copy"` 或不写：优先使用拷贝的部件；我们的关卡工具写入 `"own"`）。在该文件上录制的回放可以在转换后的关卡上播放（同一关卡，因此同一过程）；格式错误的设置会使关卡被拒绝。任何关卡都可以写上任何哈希，因此能在它上面播放的回放并不能证明在原版上跑过。没有设置的关卡（在保存设置之前制作的）使用默认值游玩，并会说明这一点；重制的 `Level_NN` 则改从拷贝的关卡表中取得设置。`game/` 中的游戏文件只代替关卡自己的部件、天空、粒子、阴影和一局游戏的声音：界面的文件（菜单、字体、关卡表、菜单声音）从不来自关卡：它们属于界面（我们的或拷贝的），并且读取的每个文件都有大小上限。
- **雾** `settings.fog`（我们的关卡），只用于绘制：离相机远的东西融入空气的颜色——朝地平线方向为 `color`，正下方为 `color_down`（三个 0..1 的数；没有 `color_down` 时四周同一种颜色），每单位距离的雾量 `density`（1 - e^(-density × 距离)，0..1），低于 `below` 的东西也融入其中，在其下方 `depth` 处完全融入。只作用于受光照的表面（天空、精灵和云海保持自己的颜色）；原版关卡没有雾。`color`、`density`、`below` 和 `depth` 是必需的；超出范围的值会被限制到范围内，格式错误的值会使关卡被拒绝。
- **云海** `settings.clouds`（我们的关卡；见 levels.md“云海”），只用于绘制：`top`（云顶高度；必需）、`thickness`、`cover`（0..1）、`scale`（单朵云的大小）、`sun`（指向太阳的方向）、`sun_color`、`sky`（来自上方的光）、`shadow`（阴影中；颜色为线性光，1 为白）、`haze`（每单位距离的地平线雾霭）、`under`（0..1：层下的雾霭遮住下方世界的程度）和 `wind`（每秒 x、z）。只有 `top` 是必需的；超出范围的值会被限制到范围内，格式错误的值会使关卡被拒绝。

- **纹理槽（Texture slots）**：图像的 `extras.drahtseilakt.slots` 按顺序列出作为其后续槽的图像（由多张图片组成的纹理：地图脚本用 Set Current Slot 显示的动画帧）。每个都是关卡中的另一个图像；最多 63 个；否则关卡被拒绝。
- **2D 框（Frames）** `extras.drahtseilakt.frames`（转换后地图的 2D 框：角落里的作者签名、标志；仅绘制）：每个包含 `name`、`rect`（640 x 480 屏幕像素中的左、上、右、下）、`uv`（显示的纹理部分）、`z_order`（较小者先绘制）、`material`（索引或 null）和 `visible`。最多 64 个；格式错误的会使关卡被拒绝。
- **脚本** `extras.drahtseilakt.scripts`（转换后的社区地图自带的行为图；`script_json.rs`）：`objects`（名称、类别，以及每个对象对引擎而言是什么：按索引的实体、组、网格、材质、纹理或表）、`nodes`（按对象索引的行为块、连线、IO、参数和运算）、`arrays`（地图的表）、`scripts`（顶层图及其所附着的对象），以及地图中有时的 `groups`（地图给每个组的成员）、`attributes`、`priorities`（对象及优先级：较高者先运行其脚本）、`start_off`（场景开始时处于停用状态的脚本和对象）和 `waves`（其声音：对象、文件、是否循环、音量、声像、音高）。在保存后三项之前写入的关卡读取时没有它们。只是数据，由我们的运行时驱动（[scripts.md](scripts.md)）；读取时重新推导反向引用，每个索引都会检查，格式错误的条目会使关卡被拒绝。没有该字段的关卡没有脚本（模板的火焰无论如何都由发射器帧绘制）。我们的关卡工具也会写入它们（`assets/own/make/scriptkit.py`：逐块搭建行为图，按名称引用关卡的对象、材质和纹理），展示关卡自己的行为图就是这样写的（[levels.md](levels.md)）。

## 坐标

glTF 是右手系，Virtools 是左手系，两者都以 Y 轴向上：Z 取反（位置、法线和矩阵，矩阵的 Z 行和 Z 列变号），并且每个三角形的绕序反转。取反是精确的，因此一个关卡转换后再读回，逐位完全相同：第 1 关及其开放格式副本在相同输入下给出完全相同的轨迹和完全相同的画面。

## 读取

共享的关卡来自陌生人，因此读取器把文件夹视为恶意输入：`level.gltf` 最大 64 MiB，`level.bin` 最大 1 GiB，每个访问器都对照其视图和缓冲区进行检查，索引对照顶点数检查，图片路径限制在该文件夹内，超出上述子集的任何内容都以错误拒绝。
