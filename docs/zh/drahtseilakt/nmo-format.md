# Virtools 文件格式（.nmo / .cmo）

`crates/nmo` 如何读取 Ballance 的关卡和自制地图。这些内容是从文件本身摸索出来的——游戏自带的文件以及约 600 张自制地图，全部都能完整读取——并结合了 Virtools SDK 头文件中的标识符常量。所有数值均为小端序；“字”（word）指 32 位。

## 容器

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0 | 8 | 签名 `Nemo Fi\0` |
| 8 | 4 | 校验和 |
| 12 | 4 | Virtools 版本（Ballance 所用的 Virtools 2.1 为 `0x13022002`，3.5 为 `0x26052005`） |
| 16 | 4 | 文件版本（所见文件均为 8；从 5 开始存在头部 1） |
| 20 | 4 | 零 |
| 24 | 4 | 写入模式（位 `8`：整个文件压缩） |
| 28 | 4 | 头部 1，存储大小 |
| 32 | 4 | 数据，存储大小 |
| 36 | 4 | 数据，解压后大小 |
| 40 | 4 | 管理器数量 |
| 44 | 4 | 对象数量 |
| 48 | 4 | 最大对象 id |
| 52 | 4 | 产品版本 |
| 56 | 4 | 产品构建号 |
| 60 | 4 | 头部 1，解压后大小 |

之后是头部 1，然后是数据。某一部分当且仅当其存储大小与解压后大小不同时才经过 zlib 压缩。
在数据之后，由 Virtools 3.5 写入的文件会一直追加**内含文件**直到末尾：名称（字长度 + 字节）和内容（字大小 + 字节）；通常只有 `vtthumbnail.jpg`，有些地图还带有声音和图片。

**校验和**：从 0 而不是 1 开始的 Adler-32，先计算 64 字节头部（校验和字段置零），再计算存储的头部 1 和数据（不含内含文件）。在所见的每个文件中都匹配；读取器遇到不匹配时会报告而不是拒绝，因为尚不清楚原版游戏是否检查它。

## 头部 1：对象表

每个对象：id、类 id、在数据中的索引、名称长度、名称字节（使用写入者的代码页——中文地图中常为 GBK）。其后是插件依赖，不需要读取。

## 数据：管理器与对象

首先每个管理器一条记录（GUID：2 个字，大小字，chunk），然后按表中顺序每个对象一条记录（大小字，chunk；大小为 0 表示没有 chunk）。

**状态 chunk**：一个版本字（数据版本、类 id、chunk 版本和选项位，各占一个字节）、字数、这些字，然后是由选项位选择的可选列表（`1` 对象 id，`4` 子 chunk，`2` 管理器；各为一个字数加上这些字）。选项 `8` 表示对象引用是对象表中的索引；`0xFFFFFFFF` 为空引用。

在这些字内部，字段按**标识符**分组，构成一个链表：`[标识符, 下一个标识符的索引（末尾为 0）, 字段...]`。字符串是一个字节长度加上补齐到整字的字节；写入者可能在结束的 NUL 之后留下垃圾数据。

## 构成关卡的类

| 类 | Id | 标识符 | 字段 |
|---|---|---|---|
| 任意对象 | | `0x4` / `0x18` | 存在时：隐藏 / 按层级隐藏 |
| Group | 23 | `0xFFFFF` | 数量，成员引用 |
| Material | 30 | `0x1000` | 漫反射、环境、镜面、自发光（ARGB 字），镜面指数（浮点），纹理引用，边框颜色，模式字，标志字 |
| | | `0x10000` | 效果：参数引用，效果（1 TexGen，2 带参照物的 TexGen）；参数的值是 TexGen 类型（CK2_3D.dll：None 0，Transform 1，Reflect 2，Chrome 3，Planar 4，立方体贴图 31..34） |
| Parameter | 46 | `0x40` | 类型 GUID（2 个字），一个字，字节大小，值 |
| Texture | 31 | `0x10000` | 槽数，每个槽的文件名 |
| | | `0x20000` | 内嵌像素：槽数，然后是每像素位数、宽、高、掩码 A R G B、一个压缩字（0），然后是四个平面：蓝、绿、红、Alpha，每个先是字节数（宽 x 高），再是补齐到整字的字节，行自下而上；像素位于文件中时为 `[1, 0]` |
| | | `0x2FF000` | 加载选项：一个字（`0x100` 透明色，`0x200` 后跟视频格式），然后按该段的大小依次为透明色（0xRRGGBB）、当前槽、视频格式；该颜色的纹素会被 alpha 测试丢弃 |
| Mesh | 32 | `0x100000` | 材质槽：数量，然后每槽一对（引用，字） |
| | | `0x20000` | 顶点数、保存标志、大小（数据字数 + 1），然后按标志依次为位置、颜色、镜面色、法线、UV |
| | | `0x10000` | 面数，然后每个面两个字：索引 0 和 1（各 16 位），索引 2 和材质槽 |
| | | `0x4000` | 材质通道（用另一材质再次绘制该网格，混合叠加在自身之上）：数量，然后每个通道依次为材质引用、标志（`0x1` 启用）、源与目标混合、UV 数量（0 或顶点数）以及 UV 对 |
| 3D 实体 / 对象、摄像机、灯光 | 33, 41, 34, 35, 38, 39 | `0x100000` | 一个字、标志、3×3 轴（按行）、位置——即世界矩阵 |
| 3D 对象 | 41 | `0x4000` | 当前网格引用，数量，网格引用 |
| Sprite 3D | 37 | `0x400000` | 模式（0 朝向视点，1 绕 x 旋转，2 绕 y 旋转，3 保持放置时的朝向），半宽，半高，x 和 y 偏移（半尺寸的 -1..1），纹理矩形 u0 v0 u1 v1，材质引用；以材质的漫反射颜色无光照绘制 |
| 摄像机、目标摄像机 | 34, 35 | `0xfc00000` | （数据版本 5 及以后）投影、视场角（水平，弧度）、正交缩放、宽高比（宽、高各为 16 位的一半）、近裁剪面和远裁剪面 |
| 目标摄像机 | 35 | `0x10000000` | 其目标对象 |
| Curve | 43 | `0xffc00000` | （数据版本 5 及以后）控制点：数量和按曲线顺序排列的引用，拟合系数，步数，开放标志 |
| Curve point | 36 | `0x10000000` | （数据版本 5 及以后）所属曲线，用户切线（代替 TCB），线性，张力，连续性，偏移，入切线和出切线（曲线局部坐标） |
| Data array | 52 | `0x1000` | 列：数量，然后是名称（字符串）和类型（1 int，2 float，3 string，4 object，5 parameter + 类型 GUID） |
| | | `0x2000` | 行：数量，然后每列一个值 |

**顶点保存标志**：`0x1` 所有顶点共用一个颜色，`0x2` 共用一个镜面色，`0x4` 无法线（读取器计算平滑法线），`0x8` 共用一个 UV，`0x10` 无位置。

**材质模式字**，从最低位起按半字节依次为：纹理混合模式、缩小过滤、放大过滤、源混合、目标混合（Virtools 混合因子：1 zero，2 one，3 src colour，4 inv src colour，5 src alpha，6 inv src alpha，…）、着色模式、填充模式。**标志字**：位 `0x1` 双面，`0x2` 深度写入，`0x8` alpha 混合，`0x10` alpha 测试；字节 1 为深度比较，字节 2 为 alpha 比较，字节 3 为 alpha 参考值。

## 游戏从关卡中读取什么

关卡包含几何体和**组**；游戏逻辑位于 `base.cmo` 中，按组名工作：
`PS_Levelstart`（起点；其 Z 轴指回摄像机）、`PR_Resetpoints`（每个小节的球心位置）、`PC_Checkpoints`、`PE_Levelende`、`Sector_NN`、`Phys_Floors` / `Phys_FloorRails` / `Phys_FloorStopper`（碰撞）、`P_*`（机关和道具，其模型来自 `3D Entities/PH/*.nmo`）、声音组。
`P_*` 组的成员是占位物：游戏在它的位置生成与组同名的机关，不论该成员叫什么名字、长什么样、是否隐藏（Blender 制作的地图把它命名为 `P_Modul_26_01_.001`，并给它零件本身的网格和材质）；占位物本身不绘制。在原版关卡中，占位物是没有材质的可见网格，以其机关命名。没有材质的地板、轨道或挡板属于关卡几何体，以纯色绘制。各关卡的天空和初始球位于 `3D Entities/Levelinit.nmo` 的数据数组 `AllLevel` 中。
